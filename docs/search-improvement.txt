The “powerful trick” I mentioned is called entity embedding lookup (sometimes called semantic entity resolution).
Instead of writing n-gram rules or relying only on DB string matching, you create a small vector index of just your product titles and let embeddings detect which title the user meant.

This works extremely well for:

typos

different word order

partial names

extra words in the question

And it avoids complicated phrase extraction logic.

Core Idea

Create two vector indexes:

1️⃣ Title index (small)
2️⃣ Content index (your existing Qdrant RAG index)

Then query the title index first.

If a title is detected with high confidence → treat it as an entity.

Step 1 — Create a Title Vector Index

For each painting title, generate an embedding and store it.

Example data stored in Qdrant collection painting_titles:

id	title	embedding
1	Golden Evening	vector
2	Dashashwamedh Ghat	vector
3	Dashashwamedh Ghat Top View	vector
4	Dream	vector
5	Fantasy	vector

The text you embed should be slightly enriched:

Painting title: Golden Evening

or

This helps the embedding model understand context.

Step 2 — Query the Title Index

User query:

Generate embedding for the whole query.

Search in the title vector index.

Step 4 — Only Use Qdrant RAG If No Entity Found

Now run semantic search in your main Qdrant collection.
