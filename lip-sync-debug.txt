Ah — that detail changes the diagnosis completely.
If there is no lip movement at all and instead you see an oval animated shape below the lips, then the lip-sync model is not actually driving the mouth mesh. What you are seeing is likely a fallback mouth animation layer (a simple amplitude animation reacting to audio).

This usually happens when the real lip-sync step failed silently, and the renderer switched to a placeholder mouth animation.

Based on the pipeline Copilot described, here are the most likely reasons.

1️⃣ The lip-sync model never ran

Your log line mentioned:

avatar_applied=True
avatar_error=False

But that only confirms the avatar overlay worked, not the lip-sync stage.

If the pipeline order is something like:

TTS audio
→ lip-sync generation
→ avatar overlay
→ ffmpeg render

and lip-sync generation fails, the renderer still produces a video.

Typical fallback behavior:

mouth area = static image

audio amplitude animation = oval shape below mouth

So the video looks alive but mouth never moves.

2️⃣ The wrong avatar asset was used

Many avatar systems require special prepared avatars where the mouth region is separable.

Example structure:

avatar_base.png
avatar_mouth_mask.png
avatar_landmarks.json

If the avatar lacks facial landmarks, the system cannot move lips.

Result:

mouth stays static

fallback animation appears

3️⃣ Face landmark detection failed

Lip-sync models require face detection + mouth landmarks.

Common reasons for failure:

avatar face too small

face angle not frontal

lighting too dark

avatar is stylized / illustration

When this happens:

face_detected = False

and lips cannot animate.

4️⃣ Audio features were not extracted

Lip models use mel spectrograms from the audio.

If audio preprocessing failed:

mel_features = None

the renderer cannot drive lip movement.

Some pipelines then default to simple amplitude animation (the oval shape you see).

5️⃣ The mouth layer is missing transparency

Copilot switched formats:

VP9 WebM → MOV (qtrle + argb)
format=rgba

If the alpha channel isn't preserved, the animated mouth frames exist but get hidden behind the base avatar.

Result:

lip frames exist
but invisible

The oval animation you see may be below the overlay layer.

6️⃣ The lip-sync module wasn't included in the job

Sometimes job configs look like:

{
 "avatar": true,
 "lipsync": false
}

In that case the pipeline just does:

avatar + audio

without lip movement.
